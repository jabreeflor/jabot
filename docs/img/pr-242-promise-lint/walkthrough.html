Add type-aware lint checks for unhandled and misused promises

One shared ESLint config now sits in the same verification gate as tsc. Official React Hooks rules are the foundation (#224 had no PR). Type-aware no-floating-promises and no-misused-promises are the #225 extension. There is no second linter.

How it works

Before

  • Strict TypeScript allowed discarded promises and async functions where a void callback was expected.
  • A rejected onClick={async () => …} never failed a gate.
  • No frontend lint command existed for later issues to extend.
→

After

  • eslint.config.js is the one config. Hooks come from the official plugin; promise rules are type-aware via projectService.
  • npm run lint is the same command verify.sh runs, including --fast.
  • Probes in scripts/tests/lint-rules.mjs prove the rules fire, then disappear — they never live in the tree.
src/ tests/ scripts/dev/ vite.config.ts vitest.config.ts
Fails the run Promise.resolve() with no await / return / void. An async function assigned to () => void or a JSX onClick. A conditional hook. A missing effect dependency.
Passes awaited work, a returned promise, or void work.catch(…). Event handlers that return void and start work whose callee already reports the failure.

JSX event-handler attributes stay checked. There is no checksVoidReturn.attributes: false exemption — that would hide the exact rejected-promise bug this issue asked to catch. void marks deliberate background work; the error strategy is either the callee or a .catch on the same expression.

How to verify

  • npm run lint — ESLint over the tree, then the probe script. Offline after npm install.
  • Break a probe: comment out no-floating-promises in eslint.config.js and watch scripts/tests/lint-rules.mjs fail.
  • Put onClick={async () => { await Promise.resolve(); }} on a first-party button and watch no-misused-promises fail. Do not add checksVoidReturn.attributes: false to silence it.
  • ./scripts/verify.sh --fast includes the same npm run lint command.
