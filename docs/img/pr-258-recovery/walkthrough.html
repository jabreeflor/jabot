Playwright coverage for host recovery, worktrees, schedules, and PR workspace

Issue #233 on top of the shared real-host fixture from #256. Chromium drives the React renderer; a dedicated Vite + jabot-hostd owns a temp data directory. No forked harness.

How it works

Each test calls startJabotApp() — own port, own SQLite dir, never port 1420.
jabot.stopHost() SIGKILLs only jabot-hostd. Vite stays up. The bridge emits host/disconnected; the sidebar shows the error and Reconnect.
jabot.restart() is a Vite restart. page.reload() is a browser reload. Test titles name which one they exercise.
PR tests prepend a fixture gh to PATH before Vite starts. Tokens never leave the fixture; GraphQL/REST answers are files.

Reload vs Vite restart vs host restart

MechanismWhat diesRecovery
Browser reloadThe tab / HostClientuseHost() runs again
Host restartjabot-hostd onlyReconnect (or a later RPC) respawns on the same data dir
Vite restartVite, HMR, and the hostNew Vite; the page must navigate again

How to verify

npm run host:build && npx playwright install chromium

npx playwright test --project=chromium

CI browser job runs that same Chromium suite. ./scripts/verify.sh stays offline; --check-browser is the local opt-in.

What this does not prove

Native dialogs, macOS Keychain, Tauri IPC, packaged WKWebView, and mobile browsers remain #235. Fixture gh does not claim GitHub API compatibility.
