JaBot · PR walkthrough · #301 · issue #296

Pick the model from a compact chip. The adapter actually receives it.

New Chat already had workspace / harness / host chips. The model Select existed but was gated on supports_models, which only OpenCode advertised. Claude Code is the default and was false, so the chip never showed. Conversation had no model control at all.

How it works

Catalog

  • Claude, Cursor, and OpenCode set supports_models: true.
  • No hardcoded vendor id lists.
  • Custom files may opt in; Fake ACP does, so the live loop can advertise real ids.
→

Listing

  • Doctor parse: slash ids, bare ACP ids, JSON.
  • Cached availableModels from session/new.
  • Bounded ACP probe when the card is ready and the list is empty.
  • Always include Harness / Project default.
→

Apply

  • thread/open stores the pin and last-used per harness.
  • thread/set_model updates runtime_json.
  • Live: session/set_model → set_config → set_config_option.
  • If it cannot switch live, the UI says so. Never a silent no-op.

Decisions

ChoiceWhy
Harness picker stays its own chipThe model menu is not a second way to pick Claude vs OpenCode.
Options come from the adapterA missing CLI disables the chip with the Doctor reason. No fake Sonnet/Opus menu for Claude on a machine that cannot name those ids.
Harness switch resets the pinNew Chat keeps a per-harness map so switching back does not leak the previous engine's id.
Empty model = defaultOpenCode: Project default. Everyone else: Harness default. Applied on next spawn if there is no live session.

How to verify

  • ./scripts/verify.sh — the land-on-main gate. Already green on this tree.
  • New Chat + Claude Code: a Model chip. If Claude is missing, it is disabled with the install hint.
  • OpenCode still lists Doctor / opencode models results and still passes model on thread/open.
  • Start a thread, then change the chip. thread/state shows the pin. A live adapter gets session/set_model (or equivalent); otherwise the status line names next spawn.
  • Switch harness in New Chat: the model resets. Switch back: the previous harness's id does not leak.
