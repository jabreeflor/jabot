Diagnose Claude Code harness turns that end without a reply

An empty Claude Code turn is still a failed turn. The host now names the prerequisite that failed — sign-in, CLI, model, launch, or a process that exited — and puts the adapter log on the same line so a retry has something to fix.

How it works

Before

end_turn + no visible text → empty_response

Header: failed: no reply

Sys line listed every possible cause and identified none. A process that died mid-prompt closed the run as adapter_exit without a transcript line.

After

Same empty-reply gate from #183 / #203, plus stderr classification

Header: failed: not signed in, failed: model, failed: adapter exited, …

Sys line is the sentence for that cause, then Adapter log: and the tail of the harness stderr. Composer stays open for retry.

Classification is a read of the adapter’s *.stderr.log at the moment the turn ends with no visible reply, or the process exits before a session/prompt response. Unknown output stays empty_response / adapter_exit and still carries the excerpt.

What to look at

  • src-tauri/src/host/acp/no_reply.rs — classify stderr into sign-in, CLI, model, launch, or exit.
  • src-tauri/src/host/acp/mod.rs — empty end_turn and process-exit both persist a diagnostic state_update.
  • src/views/transcript.ts — specific header labels; sys line prefers the host’s error and adapter log.
  • src-tauri/src/bin/fake_acp_agent.rs — empty-reply-logged-out, empty-reply-model, exit-before-reply.
