Add Jabot app awareness and conversational bot drafts

Chief or Bot Recruiter can propose a crew member. Save creates the bot. Every session/prompt carries versioned Jabot context and the current persona.

How it works

1. Propose An allowed bot calls draft_bot on the existing MCP bridge. The host persists a draft and returns saved: false.
2. Review Full-device UI lists pending drafts. Close is not Dismiss. Approver phones cannot Save.
3. Save Atomic host Save creates one crew member. Opening chat uses crew/thread. No run starts.

Before every ACP dispatch the host prepends one text block: packaged Jabot instructions, current bot, current thread, then the user’s original blocks. The transcript stays exact. There is no invented systemPrompt.

What to look at

  • src-tauri/src/host/acp/prompt.rs — composition used by direct and queued dispatch
  • src-tauri/src/host/crew/draft.rs — MCP tools, UI RPCs, validation, stale policy
  • src-tauri/src/host/store/draft.rs — durable drafts and atomic Save
  • src/App.tsx + BotEditorModal.tsx — Proposed by, pending list, Open chat
  • src-tauri/src/host/store/seed.rs — default grant and upgrade of untouched seats

Policy

Draft-first. Save is UI-only, never an agent tool.

Default grant: untouched Chief and Recruiter only.

Omitted harness: template, then source bot, then thread.

No MEMORY.md, tokens, or credentials in the prompt.

Stale drafts stay reviewable. Save is a fresh user action.

Drafts are not Inbox permission cards.

How to verify

  1. Run ./scripts/verify.sh.
  2. Ask Chief to make a research bot; confirm a pending draft and no new crew row.
  3. Save in the editor; Researcher appears. Open chat uses the standing thread.
  4. Check a captured session_prompt= for Jabot context v1 and the persona; the transcript is only the user text.
