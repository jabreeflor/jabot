Add Playwright Test infrastructure against the real Rust host

A reusable browser harness that talks to a real jabot-hostd, not jsdom and not the shared live.sh data directory. One smoke journey lands now; #232–#234 reuse the fixtures.

How it works

Before this PR, protocol tests spawned the Rust host without a renderer, and React tests ran in jsdom. playwright-core existed only for live.sh shot. There was no Playwright Test suite and no browser CI gate.

Before

Vitest e2e → HostClient → jabot-hostd. Renderer never loads. jsdom covers React in isolation.

After

Each test owns Vite + host + temp SQLite. Playwright clicks the real composer. Protocol e2e stays.

Playwright Chromium (or WebKit) React renderer (Vite, JABOT_LIVE_HOST=1) src/host/devTransport.ts → Vite HMR bridge scripts/dev/host-plugin.ts / host-bridge.ts jabot-hostd --data-dir $TMP → SQLite fake-acp-agent only — no Claude, no GitHub, no Keychain

Readiness is GET /__jabot/host with running: true and a hello payload, then the Settings control with “Connecting to host…” gone. HTTP 200 alone is not enough.

Isolation: listen on a free loopback port (never 1420), write JABOT_DEV_DATA_DIR to a temp folder, spawn Vite as a process group. jabot.restart() reuses that folder. Teardown SIGTERMs the group and deletes only the owned directory.

How to verify

Local, one command, no credentials:

npm run host:build && npx playwright install chromium && npm run test:browser:smoke

Runs against a fresh temp host. Do not use live.sh smoke for this suite.

CI: the browser job on this PR. Failure artifacts upload even when the job fails.

Opt-in on verify: ./scripts/verify.sh --check-browser

WebKit: npm run test:browser — renderer compat only, not native WKWebView.
