JaBot · Issue #221

Add GitHub Copilot CLI as a first-class harness

Copilot joins Claude, Codex, and Pi as a shipped card. JaBot speaks to the vendor CLI over ACP (copilot --acp). There is no second adapter package.

How it works

Before

  • Shipped ids were claude, codex, pi.
  • Doctor classified those by CLI vs adapter vs login.
  • Copilot was research-only.
→

After

  • copilot is a shipped card that launches copilot --acp.
  • Doctor inspects help text, tokens, ~/.copilot, and model pins.
  • Capabilities are declared; resume is not advertised.

The CLI is the ACP server. A one-shot copilot -p path exists upstream but has no permission mediation and is not used for chat. JaBot does not wrap the TUI.

Doctor and auth

Org / subscription policyinvalid_configLicense + org admin; not a login problem

Token precedence matches Copilot: COPILOT_GITHUB_TOKEN, then GH_TOKEN, then GITHUB_TOKEN, then copilot login. A deep handshake reclassifies policy / 401 / bad model instead of “unknown”.
