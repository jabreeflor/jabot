PR walkthrough

Import jabstack as Cursor and Codex workspace plugins

JaBot already pinned jabstack for Claude Code. This change vendors the plugin in-repo and registers it so Cursor and Codex load the same skills from the workspace.

How it works

One plugin tree, two native manifests, two repo marketplaces. Skills stay in a single skills/ directory. Each harness discovers that tree through its own catalog format.

Before

Claude CodeGitHub marketplace pin in .claude/settings.json
CursorNo plugin in this repo
CodexNo plugin in this repo
→

After

Claude CodeUnchanged: still jabstack@jabstack from GitHub
Cursor.cursor-plugin/marketplace.json + workspace enable
Codex.agents/plugins/marketplace.json installs by default

Trade-off: the tree is a snapshot of jabstack 0.3.0 (7d1c29c), not a live submodule. That keeps plugin paths local and offline. Update plugins/jabstack/ when upstream releases; SOURCE.md records the pin.

What to look at

How to verify

  1. Confirm manifests parse and paths exist:
    python3 -c "import json,pathlib; json.loads(pathlib.Path('.cursor-plugin/marketplace.json').read_text()); json.loads(pathlib.Path('.agents/plugins/marketplace.json').read_text())"
    and test -f plugins/jabstack/skills/create-pr-artifact/SKILL.md
  2. Cursor: reload the window, then open Customize and confirm gauntlet-loop, create-pr-artifact, and gauntlet-critic. Optional local fallback: ln -sfn "$(pwd)/plugins/jabstack" ~/.cursor/plugins/local/jabstack
  3. Codex: start a new conversation in this repo and ask to run /create-pr-artifact or “run the gauntlet”. The repo marketplace should offer jabstack without a Git clone of jabreeflor/jabstack.
  4. Claude Code: unchanged — accept jabstack@jabstack from .claude/settings.json.
  5. No app UI change: skip visual regression. ./scripts/verify.sh --fast is enough for the existing gate.
