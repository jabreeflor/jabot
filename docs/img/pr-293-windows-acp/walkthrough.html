Windows ACP adapter process lifecycle (Job Objects / kill-tree)

Issue #285 (parent #280). The host already spawned one ACP adapter per live thread and killed a Unix process group. Windows only set CREATE_NEW_PROCESS_GROUP and then Child::kill() — one PID, so Node/.cmd grandchildren leaked. This PR adds a real kill-tree and fixes PATHEXT / path separators. Unix teardown is the original SIGTERM-then-return (no immediate SIGKILL of the group).

How it works

Unix (unchanged) process_group(0) Child pid becomes the pgid. SIGTERM the group; if the direct child exits, return. SIGKILL only if it is still alive after grace.
→
Windows (#285) Job Object Nameless job with KILL_ON_JOB_CLOSE. CREATE_SUSPENDED → assign → ResumeThread (birth-into-job). Descendants inherit unless they break away.
→
Then teardown CTRL_BREAK + terminate Grace via GenerateConsoleCtrlEvent (skipped when it fails), then TerminateJobObject. Fallback: taskkill /T /F whenever the job was not assigned — including after the wrapper pid has already exited.
Why not CREATE_NEW_PROCESS_GROUP alone?

That flag only affects Ctrl+Break delivery. It does not put children in a killable group the way a Unix pgid does. Child::kill() is still TerminateProcess on the pid we spawned. Job Objects are the Windows equivalent Buzz already documented (KILL_ON_JOB_CLOSE, then taskkill /T /F if assignment fails because a parent job forbids nesting).

Path and PATHEXT

Doctor and spawn used to disagree on Windows: resolve only appended .exe, but npm adapters are .cmd shims. CreateProcess walks PATHEXT; now so do we.

  • Walk .COM;.EXE;.BAT;.CMD (or the process PATHEXT).
  • Do not double-extend: node.exe is not node.exe.exe.
  • Try both .CMD and .cmd so a case-sensitive volume (WSL) still finds npm shims.
  • Join with Path::join — never hard-code \ vs /.
  • Home is $HOME or USERPROFILE. Well-known Windows dirs (%APPDATA%\npm, %ProgramFiles%\nodejs) are appended the same way.
