Add subtle Cursor-style window translucency

Almost-opaque chrome, a faint desktop hint, and a hard opaque fallback. Closes #250 without touching the light/dark palettes.

How it works

1. Native material, macOS only The main window is transparent. Setup applies Tauri Effect::UnderWindowBackground (Cursor’s Electron under-window equivalent) and clears the webview fill. Linux/Windows set_effects fails; the command reports false and CSS never mixes.
2. Renderer paints one attribute bootTranslucency() asks window_translucency_applied. If the material stuck — or the URL is ?translucency=preview for live.sh shots — it sets data-translucency="on". Reduce Transparency clears it.
3. Fills mix; raised surfaces do not --side-fill / --chat-fill become a 96% / 97% color-mix of the existing theme tokens. Search, composer, selected rows, and Settings controls stay on solid --raise / --cream. Body goes transparent so the two panes do not stack mixes.

What to look at

FileWhy it matters
src-tauri/src/window.rs Applies the material and exposes whether it stuck.

src-tauri/tauri.conf.json transparent + declarative windowEffects.

Platform limits

macOS 13+ gets the material. Linux has no Tauri window effects (this live.sh path). Windows Mica/Acrylic are left off — a different look, not tuned against Cursor. Missing material or prefers-reduced-transparency: reduce keeps every surface on the solid theme tokens.

How to verify

  1. On a Mac: npm run tauri dev, park the window over a light wallpaper, then a dark one. Both themes.
  2. Turn on Reduce Transparency — chrome should go fully opaque.
  3. On Linux: ./scripts/live.sh up then ./scripts/live.sh shot --out /tmp/after.png --desktop light --translucency preview.
  4. ./scripts/verify.sh on the pushed tree.
