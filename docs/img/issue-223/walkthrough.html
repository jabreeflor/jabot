Add Aider harness integration

JaBot can now start Aider threads. Aider still does not speak ACP — JaBot wraps its scripting CLI and says so in the catalog, Doctor, and initialize.

How it works

PickerCatalog id aider is a reserved preset. Onboarding, Settings, New Chat, and the crew editor all read the same list.
DoctorAsks aider on PATH, then --version ≥ 0.35, then an API key, then a model. Each miss has its own remedy.
Spawnjabot --aider-acp (or jabot-hostd --aider-acp) speaks ACP stdio. It is not a third production binary.
TurnOne session/prompt becomes aider --message-file … --yes --no-auto-commits --no-dirty-commits --stream in the thread cwd.
ContextPer-session --chat-history-file under $TMPDIR/jabot-aider/ plus --restore-chat-history.
FailureSpawn errors and non-zero exits return stopReason: error plus visible text. Empty stdout is end_turn (host maps that to empty_response).

What we do not claim

Native ACP is _meta.jabot.nativeAcp: false. Permission prompts are unsupported — the adapter always passes --yes. Aider’s config is user-global; two bots cannot have different Aider accounts. Auto-commits stay off so JaBot owns the worktree.

How to verify

  1. ./scripts/verify.sh on this branch (already green on the pushed tree).
  2. Install Aider and export a provider key, then start a thread on Aider in a folder worktree.
  3. Confirm Doctor names a missing binary / old version / missing key / missing model instead of a generic “not installed”.
  4. Confirm git log in the worktree has no Aider auto-commits.
