Windows CI verify so the port does not rot

Linux verify compiles straight past #[cfg(windows)]. This PR adds a lean windows-latest compile + portable test job, and an unsigned NSIS build that is opt-in — not every PR. Minutes stay cheap; failures stay real.

How it works

1. Plan (Linux, always)

  • windows-needed.sh classifies the PR diff.
  • Docs / renderer-only → verify=0.
  • Host / toolchain / this workflow → verify=1.
  • Tags and dispatch force verify.
→

2. Verify (Windows, gated)

  • Stub adapters (no npm ci).
  • cargo check --locked without dev-bins.
  • Clippy -D warnings on all targets.
  • Portable cargo test.
  • No continue-on-error:.
→

3. Package (opt-in)

  • Unsigned NSIS only.
  • On v* tags, windows-package, or dispatch package=true.
  • --bundles nsis does not change macOS app/dmg.
  • Full release path is still #281.

What to look at

  • .github/workflows/windows.yml — sibling workflow; Ubuntu and macOS jobs are untouched.
  • scripts/windows-needed.sh + scripts/tests/windows-ci.test.sh — the path list that spends 2x minutes, tested so it cannot silently stop matching.
  • scripts/windows-verify.sh — the exact cargo stages CI runs.
  • docs/windows-ci.md — guarantees vs human smoke.
  • src-tauri/tests/common/mod.rs and two host tests — .exe, git, and Unix symlink so the Windows job can stay red-means-broken.

How to verify

  • ./scripts/tests/windows-ci.test.sh — 17 offline cases; part of ./scripts/verify.sh.
  • ./scripts/windows-needed.sh --base origin/main — would this PR start a Windows runner?
  • On the PR: windows plan is green; windows verify runs because this change touches src-tauri/ and the new workflow.
  • Label windows-package only if you want an unsigned NSIS artifact. That is not required to land #286.
