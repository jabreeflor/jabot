Prepare adapters before the first conversation

Onboarding checks the selected engine before the first prompt and offers a direct install for missing Claude, Codex and Pi ACP adapters.

How it works

Previously, setup saved the engine choice and a missing adapter surfaced when starting a conversation.

Choose engine → Check adapter → Install or skip → Check readiness → Continue

The installer runs in the background. A one-second status poll keeps the screen responsive. Failed checks and installations remain visible with retry and skip controls.

What runs on the host

The new harness/install RPC accepts only three built-in harness IDs. Each maps to a pinned npm package; catalog hints and arbitrary package names never become commands. npm installs into ~/.local without a shell or sudo. Installs are serialized, and the process group is stopped after 180 seconds.

The engine CLI and account sign-in remain separate prerequisites. The Doctor reports those failures after adapter installation. Harnesses disabled in Settings are excluded from onboarding choices.

What to review

harness/install.rs — allowlist, background status, serialized jobs and timeout.
AdapterSetup.tsx — readiness, install polling, connection-error recovery and skip.
Onboarding.tsx — prepare the selected enabled engine before finishing setup.

How to verify

Run ./scripts/verify.sh. In first-run setup, continue to the engine picker, choose Codex and continue. When its adapter is missing, confirm the install action and retry/skip controls. An installed engine shows readiness. Unit coverage exercises success, failed installs, lost polling connections and retry.

Real-host evidence: adapter-check.png. Package versions and executable names were confirmed using npm registry metadata. No global adapter was installed solely for the screenshot.
