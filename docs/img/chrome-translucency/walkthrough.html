Give the desktop chrome a slight glass treatment

Extends #250 so every chrome surface — panes, raised chips, composer, and modals — shares one slight mix. Cream, ink, and BotMark art stay solid.

How it works

1. Same on-switch as #250 bootTranslucency() still paints data-translucency="on" only when native under-window vibrancy stuck, or when live.sh asks for ?translucency=preview. Reduce Transparency, Linux, and Windows stay on the solid swatches.
2. One pair of tokens per surface Each paint color has a --*-solid swatch. Semantic names (--side, --raise, --sunk, --bub-me) alias it until glass is on, then become a 92–96% color-mix. Light theme only reassigns the solids, so there is no second palette.
3. Raised stays above the pane Panes mix more (92–93%) than chips (94–96%) so search, selected rows, and the composer still read as raised. Cream buttons, ink, and hairlines never mix.
4. Frost only on floating chrome --chrome-frost is blur(16px) saturate(1.12) on modals, menus, and input pills. Panes mix without a filter so the desktop hint stays a faint grid, not a muddy wash. Overlay dims via --overlay without a second blur.

What to look at

File Why it matters
src/styles/tokens.css Solid swatches, mix percents, frost token, Reduce Transparency reset.
src/styles/shell.css Where backdrop-filter is applied — floating chrome only.
src/styles/modal.css Overlay reads --overlay so the dimmer follows the same switch.
src/translucency.ts Unchanged decision: native, preview, or opaque.

How to verify

  1. On a Mac: npm run tauri dev, park the window over a light wallpaper, then a dark one. Both themes. Search, composer, and a modal should hint through without losing contrast.
  2. Turn on Reduce Transparency — every surface should go fully opaque.
  3. On Linux: ./scripts/live.sh shot --out /tmp/after.png --desktop light --translucency preview --click 'text=Chief'
  4. ./scripts/verify.sh on the pushed tree.
