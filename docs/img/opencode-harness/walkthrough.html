Add OpenCode as a shipped ACP harness

OpenCode joins Claude, Codex, and Pi as a tier-1 card. The CLI is the adapter: JaBot spawns the documented opencode acp stdio transport. No extra npm package, no TUI wrap.

How it works

Catalog

Shipped id opencode. Launch is opencode acp. Settings, onboarding, New Chat, and the bot editor all read harness/list, so one card wires every picker.

→

Doctor

Three probes, three fixes: acp --help (upgrade), auth list (login or export a key), models (set opencode.json or pick in New Chat). Never run opencode acp as a probe — it hangs.

→

Session

Same ACP client as everyone else. A New Chat model is snapshotted on the thread, passed on session/new, and applied via OPENCODE_CONFIG_CONTENT so the project file is not rewritten.

streaming tools permissions cancel resume empty → failed, not success

Host MCP still comes from the bot allowlist. JaBot’s permission broker still answers session/request_permission. OpenCode may also load MCP from the project opencode.json — a deny in JaBot is still a deny.

Auth is one global ~/.local/share/opencode/auth.json. OPENCODE_CONFIG_DIR does not isolate credentials. Concurrent accounts need a dedicated data directory; JaBot will set that when #218 lands.

How to verify

  • Settings → Harnesses includes OpenCode; unchecking it drops the card from New Chat and the bot editor.
  • New Chat → Harness → OpenCode shows a model chip and the opencode.json hint.
  • Onboarding engine pane lists OpenCode. Doctor shows install / login / model, not “Install adapter”.
  • cargo test --features dev-bins --test opencode — five cases against fake-acp-agent.
  • ./scripts/verify.sh on this tree.
  • This environment (and CI) does not install the real OpenCode CLI. A machine that has it should run opencode auth login and send one live prompt.
