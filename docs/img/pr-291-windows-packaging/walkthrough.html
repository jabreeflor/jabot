Windows NSIS packaging and release artifacts

#281 / PR: add a Windows installer next to the existing macOS dmg, without letting that job rewrite latest.json.

How it works

Before / still true

  • tauri.conf.json targets stay ["app", "dmg"] (D-005).
  • One macOS job builds universal-apple-darwin, signs, notarizes, writes latest.json.
  • Updater plugin remains macOS-only. Identifier com.jabot.app, name JaBot.

After

  • tauri.windows.conf.json overlays targets: ["nsis"] on Windows only.
  • Sibling windows job on windows-latest uploads *-setup.exe.
  • uploadUpdaterJson: false, no createUpdaterArtifacts, no APPLE_*, no TAURI_SIGNING_*.
  • Same releaseBody as macos (draft notes race). npm script-shell = Git Bash before tauri build.
tag vX.Y.Z ├─ macos → .dmg + .app.tar.gz + .sig + latest.json + install.sh │ (writes full releaseBody) └─ windows → JaBot_*_x64-setup.exe │ uploadUpdaterJson: false │ same releaseBody (tauri-action will not update a draft) └─ same draft GitHub Release latest.json is written only by macos

Why NSIS is not in the base targets array

Putting nsis next to app/dmg would make a macOS tauri build see a Windows target. The overlay file is merged only on a Windows host, so D-005 stays intact: losing app still ships an unupdatable macOS feed. Release CI also passes --bundles nsis so the installer is explicit if the overlay is ignored.
