Add consistent frontend formatting with a verification check

Rust already had cargo fmt --check. The renderer did not. Prettier is now the one frontend formatter, with a read-only check in verify.sh (including --fast) so TS/JSX/CSS cannot drift past the same gate CI already runs.

How it works

Before

  • Frontend layout was whoever last touched the file.
  • Review noise was wrap, spacing, and trailing commas.
  • Nothing in verify.sh failed on a misformatted .tsx.
→

After

  • One config: prettier.config.mjs (80 cols, double quotes, semis).
  • npm run format:check is read-only; npm run format rewrites.
  • The check is a verify.sh stage, cheapest-first, offline after npm install.
Fails the run A first-party TS/TSX, JS/MJS, CSS, or JSON file that Prettier would rewrite. The contract test plants a dirty src/probe.ts and asserts --check names it.
Does not fail Vendored /plugins/, src-tauri/vendor/, generated src-tauri/gen/, lockfiles, node_modules, dist, nested worktrees, markdown, HTML, YAML. --write must leave those bytes alone.

What to look at

CONTRIBUTING.mdUsage. Prettier owns layout; lint (#224+) owns correctness and must not restate style.

How to verify

  • npm run format:check — clean on this tree.
  • npm run test:format — 12 cases, including a dirty file that fails then a write that restores.
  • Deliberately break a first-party file, watch format:check fail, run npm run format, watch it pass again.
  • ./scripts/verify.sh --fast includes the same check. No network after npm install.
  • Two review commits: gate/docs/tests first; mechanical rewrite of first-party files second. Rubber-stamp the second.
