Upgrade project tooling to Node.js 26 Current

CI, release, and local pins now track Node.js 26 (Current as of 2026-09-07, e.g. v26.8.1) instead of LTS 22. TypeScript, Vite, Vitest, Tauri, and the bundled ACP adapter all run on Current; the one real break was jsdom losing localStorage to Node’s experimental Web Storage stub.

How it works

Before

  • GitHub Actions used node-version: 22 in CI and release.
  • No .nvmrc, .node-version, or engines field.
  • Docs and live.sh said “CI uses node 22”.
→

After

  • CI verify, CI bundle, and release all use 26.
  • Local pin is the same major: .nvmrc, .node-version, engines.node: ">=26".
  • verify.sh already reads the CI pin and warns if your major differs.

The one Current break Node 25+ installs a stub globalThis.localStorage. jsdom then skips its Storage, and every unit test that calls window.localStorage.clear() crashes.
The fix Vitest workers get --no-experimental-webstorage via root poolOptions. jsdom owns Storage again. App build, adapters, and e2e did not need a fallback to LTS 24.

Lockfile churn is the root engines field only. No dependency versions or resolved URLs changed. npm ci still installs the existing tree (npm 11.19.0 on Node 26.8.1).

How to verify

  • nvm use (or install 26) so node -v is v26.x. verify.sh prints the versions at the top.
  • npm ci — installs the existing lock without rewriting it.
  • npm test — 553 unit tests. Without the Vitest flag this suite dies on localStorage.clear.
  • ./scripts/verify.sh — the full gate. This PR’s tree passed it on Node v26.8.1 / npm 11.19.0.
