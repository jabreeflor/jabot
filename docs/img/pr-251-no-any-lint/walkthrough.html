Enforce the documented no-any TypeScript policy with linting

CONTRIBUTING said TypeScript is strict with no any. tsc --noEmit only rejects implicit any. This PR adds @typescript-eslint/no-explicit-any to the shared frontend ESLint config so an annotation or an as any cast fails the same gate CI already runs.

How it works

Before

  • tsc --noEmit is strict: unused locals and implicit any fail.
  • const x: any and x as any typecheck cleanly.
  • The documented no-any policy was a house rule, not a gate.
→

After

  • The shared eslint.config.js from #224 gains one rule.
  • npm run lint (and verify.sh, including --fast) rejects both forms.
  • A stdin probe keeps the rule honest if the tree happens to be clean.

  • npx tsc --noEmit still accepts that same file. That is the point of the split.
  • ./scripts/verify.sh --fast includes the frontend lint stage. Full ./scripts/verify.sh passed on the pushed tree.
