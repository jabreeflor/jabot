JaBot · PR #277 walkthrough

Add Branch in new chat to Code messages

Every user and assistant bubble in a Code thread can fork the conversation. The child gets history through that message; the original stays put. This is conversation branching, not a Git branch — worktrees follow New Chat (a fresh checkout, never a shared one).

How it works

Before

  • A Code thread was one linear log. The only new conversation was New Chat, which starts empty.
  • Trying a different follow-up meant either overwriting the current thread or losing the earlier turns.
→

After

  • thread/branch { threadId, throughSeq } opens a sibling whose transcript is the source log through that seq.
  • The unique pair (source, throughSeq) is the child. A second click returns it; a deleted child can be replaced.
  • The header on the child links back. The original is not rewritten.
1. The renderer stamps each bubble with the last transcript_events.seq that wrote it.
2. The action row under a Code bubble calls thread/branch. Bot standing chats never get the row.
3. The host copies rows with the same seq numbers, appends a branched_from stamp, and opens the child via thread/open (same folder / harness / runtime; no useCheckout).
4. The child’s first ACP prompt prepends the copied user/agent text so the new session can continue from the cut. The UI already has the copied log.

Do not share a worktree with the source. New Chat already mints a fresh jabot/<id> tree; branch does the same.

How to verify

  • Open a Code thread (not Chief). Every finished user and assistant bubble should show the branch icon; Tab reaches it; Enter fires it.
  • Fork at an early message. The child title is Branch of …, history stops at the cut, and the header opens the source.
  • Click the same icon again — same child, not a second conversation.
  • Keep typing on the source. Those turns must not appear on the child.
